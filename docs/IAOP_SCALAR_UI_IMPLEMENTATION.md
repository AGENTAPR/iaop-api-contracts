# IAOP Scalar API Reference — Implementation Guide

## Why Scalar

Scalar API Reference provides a modern, readable API documentation UI. It renders OpenAPI 3.x specs with a clean two-panel layout, search, and code samples. Unlike Swagger UI:

- No iframe-based embedding issues
- Better OpenAPI 3.1 support
- Smaller bundle footprint
- No "Try It Out" that leaks credentials in developer portals

---

## Bundling strategy (offline / same-origin)

Scalar is distributed as a single JS file. Rather than linking to a CDN at runtime, the portal downloads the bundle **once at Docker build time** and serves it from `/static/scalar.min.js` (same origin).

**Pinned version:** `@scalar/api-reference@1.25.72`  
**CDN source (build-time only):** `https://cdn.jsdelivr.net/npm/@scalar/api-reference@1.25.72/dist/browser/standalone.min.js`

The HTML template references `/static/scalar.min.js` — no CDN URL appears in any served page.

### Dockerfile build step

```dockerfile
RUN curl -fsSL \
    "https://cdn.jsdelivr.net/npm/@scalar/api-reference@1.25.72/dist/browser/standalone.min.js" \
    -o /tmp/scalar.min.js
```

Then copied to runtime image:
```dockerfile
COPY --from=builder --chown=appuser:appuser /tmp/scalar.min.js /app/static/scalar.min.js
```

## Scalar HTML template

Each API reference page serves this HTML (generated by `routes.rs::scalar_html()`):

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8" />
  <title>{service_name} — IAOP Developer Portal</title>
  <style>body { margin: 0; }</style>
</head>
<body>
  <script id="api-reference" data-url="{spec_url}"></script>
  <script src="/static/scalar.min.js"></script>
</body>
</html>
```

- `{spec_url}` is `/specs/{spec_path}` from the catalog entry — always same-origin.
- `{service_name}` and `{spec_url}` are HTML-escaped before insertion.
- Scalar mounts itself by finding the `#api-reference` element and reading `data-url`.

## Routes

| Route | Description |
|---|---|
| `GET /reference/frontend` | Redirects to first enabled frontend service |
| `GET /reference/frontend/{id}` | Renders Scalar for the specified frontend service |
| `GET /reference/backend` | Redirects to first enabled backend service |
| `GET /reference/backend/{id}` | Renders Scalar for the specified backend service |
| `GET /static/scalar.min.js` | Serves the bundled Scalar JS (immutable cache headers) |

---

## Landing page

`GET /` serves a dark-themed HTML page (embedded Rust string literal — no external file). It fetches `/api/v1/catalog` and renders service cards using vanilla JS. No build step, no npm, no React.

Cards link to `/reference/frontend/{id}` or `/reference/backend/{id}`.

---

## Cache headers

| Asset | Cache-Control |
|---|---|
| `/static/scalar.min.js` | `public, max-age=31536000, immutable` |
| `/specs/{*}` | `public, max-age=300, must-revalidate` |

---

## Upgrading the Scalar version

1. Update the pinned version in `portal/Dockerfile`.
2. Rebuild the Docker image.
3. No code changes required (the HTML template is version-agnostic).
4. Test with `cargo test` and browser tests.

---

## CSP compatibility

Scalar JS is served from `/static/` (same origin), so the CSP `script-src 'self'` is sufficient. No `'unsafe-eval'`, no CDN allowlist, no `'unsafe-inline'` in script-src.
